# Data Model: Data Pipeline & Puzzle Counts (Epic 6)

## Overview

Epic 6 requires no new DB tables or columns. All changes are to application-level data:
- New category slug `'odd_even_threat'` registered in code
- New puzzle rows in the existing `puzzles` table (generated by factory, approved by human)
- Updated lesson JSON files (content only, no schema change)

### Puzzle rows shape (existing table)

| Column | Value for `odd_even_threat` |
|---|---|
| `category` | `'odd_even_threat'` |
| `move_string` | 0-indexed movestring from factory |
| `correct_col` | 0-indexed column whose threat lands on an odd row (Red parity) |
| `approved` | `false` initially; set `true` after human curation |
| `interaction_mode` | `'single_move'` |
| `highlight_metadata` | `null` (not needed for this category) |

### `correct_col` semantics

`correct_col` = the 0-indexed column where Red's next move creates a major threat landing on an odd row (rows 0, 2, or 4 in 0-indexed coordinates). This is the answer column for the learner.

## Predicate Output Shape

```
detectOddEvenThreat(board, scores) → {
  matched: boolean,
  correctCol?: number,        // 0-indexed; only when matched: true
  categoryEvidence?: {
    oddRowCol:  number,       // 0-indexed column of odd-row threat
    oddRow:     number,       // 0-indexed row (0, 2, or 4)
    evenRowCol: number,       // 0-indexed column of even-row threat
    evenRow:    number,       // 0-indexed row (1, 3, or 5)
  },
}
```

This shape is consistent with all other single-column detectors in `classifier.js`.

## Lesson JSON Updates

### `lesson-10-figure-7-trap.json`

| Field | Before | After |
|---|---|---|
| `slides[0].boardSpec` | hand-approximated `["dd", "dd", "", ...]` | derived from real figure_7 approved puzzle movestring |
| `slides[0].overlays` | hand-placed `(c,r)` | updated to match new boardSpec geometry |
| `_sourceMovestringForBoardSpec` | absent | added (documents the source movestring) |

### `lesson-11-j-shape.json`

| Field | Before | After |
|---|---|---|
| `slides[0].boardSpec` | hand-approximated `["dd", "dd", "d", ...]` | derived from real j_shape approved puzzle movestring |
| `slides[0].overlays` | hand-placed `(c,r)` | updated to match new boardSpec geometry |
| `_sourceMovestringForBoardSpec` | absent | added (documents the source movestring) |

**boardSpec encoding reminder**: 7-element array, one string per column (left to right). Each string lists discs bottom-to-top: `'g'` = user's discs (Yellow, since `userPerspective: "yellow"`), `'d'` = opponent's discs (Red). Empty cells are not encoded — the string ends at the top-most disc.

## Validation Script

**No new data schema.** The script reads from:
- `connect-four/lessons/*.json` (filesystem)
- `puzzles` table (Supabase direct, service role key)

Output is printed to stdout only; no writes.

**Deferred categories constant** (hardcoded in script):
```js
// These categories are excluded from the count-gate check.
// They require Epic 5 detectors (detectClaimodd, detectUndercut) which are not yet shipped.
// They are hidden from users automatically via the count=0 mechanism.
const DEFERRED_CATEGORIES = ['claimodd', 'undercut'];
```
