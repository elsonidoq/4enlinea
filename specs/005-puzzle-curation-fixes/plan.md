# Implementation Plan: Puzzle Curation & Classifier Fixes

**Branch**: `main` | **Date**: 2026-05-05 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/005-puzzle-curation-fixes/spec.md`

## Summary

Fix three systematic classifier bugs (C1: score-ambiguity for odd moveCount, C2: `===` vs `>=` winScore, C3: missing Cat 7 branch), add per-candidate debug traces and `highlight_cells` for multi-move patterns, and polish the curation UI (skip navigation, category labels, Escape key, button rename). The c4solver wrappers are consolidated into a single shared module. All changes are server-side (Node.js / JS classifier) plus React curation UI; no new external dependencies.

## Technical Context

**Language/Version**: Node.js 20 (ESM), React 18 (JSX)  
**Primary Dependencies**: Express, Supabase JS client, c4solver binary (C++, local IPC)  
**Storage**: Supabase PostgreSQL — `candidates`, `false_positive_records`, `puzzles` tables  
**Testing**: Node built-in `node:test` runner; integration tests hit the real c4solver binary  
**Target Platform**: Linux/macOS server + browser (Vite + React SPA)  
**Project Type**: Web application (Node.js API server + React frontend)  
**Performance Goals**: Classifier runs inline (no solver calls for Cat 1–3); Cat 5 PV trace requires at most K=6 additional solver queries per candidate at generation time  
**Constraints**: No extra solver calls for Cat 4 and Cat 6 highlight computation; Cat 5 PV trace solver calls happen only at generation time, not at render time  
**Scale/Scope**: Internal curation tool; ~8 known false-positive records as regression test set

## Implementation Order

Tasks must be executed in this sequence because of hard dependencies:

1. **Migration** (`009_curation_fixes.sql`) — adds `highlight_cells` and `debug_trace` columns. Must be applied before any code that inserts candidates with those fields.
2. **`classifier.js` — export guards + Cat 1/2 fixes** — add `export` to `checkWin` and `countWinningThreats`; fix Cat 1 `>=` and board-level check; add Cat 7 branch. No imports change; safe to do before wrapper.
3. **`c4solver-wrapper.js` — create shared wrapper** — no dependencies on steps 1–2.
4. **`candidate-generator.js`** — imports wrapper (step 3) and classifier exports (step 2); adds min-move enforcement, debug trace accumulation, `highlight_cells` computation, Cat 7 guard.
5. **`index.js`** — replace `Connect4Solver` with wrapper (step 3); add `highlight_cells` and `debug_trace` to the Supabase insert mapping (requires migration from step 1).
6. **UI components** — `CurationWorkspace.jsx`, `CandidateDashboard.jsx`, `RejectModal.jsx`. No server dependencies beyond the API returning new fields.
7. **Tests** — `classifier.test.js` regression fixtures (step 2); `candidate-generator.test.js` min-move and Cat 7 guard tests (step 4). Tests for the wrapper can be added alongside step 3.

Steps 2 and 3 are independent and can be parallelised. Step 6 is independent of steps 4–5 for the pure UI changes (skip, labels, Escape, button rename), but the debug panel and `highlight_cells` rendering require the API (step 5) to return the new fields.
