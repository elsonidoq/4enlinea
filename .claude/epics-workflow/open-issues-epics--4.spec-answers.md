## Blocking issue 1 — FR-001/FR-002 specify the wrong property ("per-request-unique") for the anonymous device identifier
Answer: Accept recommendation (auto-applied — no alternative). Restate FR-001, FR-002, and US1's Independent Test (spec line 34) from "per-request-unique" / "unique per originating client, never shared" to: **stable for the same originating client across requests, AND reproducible by that client on subsequent reads** (`GET /api/coach/queue`'s `device_uuid` query param, which must be UUID-formatted to pass `UUID_RE` at `connect-four/server/anonBlunderAccess.js:29-33`). Rationale, verified at source: the identifier is a cross-endpoint join key, not merely a non-shared write value — `resolveGameBlunderOwner` (`anonBlunderAccess.js:17`) stores anonymous blunders under the game row's `device_uuid`, and `src/screens/ReviewScreen.jsx:152-162` reads them back with that same value. A per-request random UUID would satisfy the current wording and SC-001 while orphaning the anonymous player's own data. (This also explains why today's `'anonymous'` rows are already orphaned: the literal fails `UUID_RE`.) Add an acceptance scenario: two successive anonymous writes from the same client land under the same identifier, and that identifier is one the client can use to read its own rows back.

## Decision 1 — Mechanism for the stable anonymous device identifier
Answer: **(b) with (a) as the server-side fallback — client sends its existing `profile.device_uuid`; the server mints a cookie-backed stable UUID only when the client genuinely has none.** The app already stores a device UUID in the local IndexedDB profile and already sends it on the games-insert path (`src/screens/GameScreen.jsx:60-77` reads `profile.device_uuid`, falling back to `''` when no local profile exists); the Challenge check path does not. So: add the identifier to the `ChallengeScreen.jsx:511` (`/api/puzzles/:id/check`) and `:603` (`/sequence/move`) request bodies, and have the server mint + set a cookie-backed UUID (all client fetches already use `credentials: 'include'`) only when no identifier arrives, echoing it in the response body so the client can use it for the `coach/queue?device_uuid=` read-back. Never return 400. Record this in the spec as a **scoped amendment to the epic's Settled decision #1** — it deviates from the literal "server-only" wording but not from its intent (never default to a shared bucket, never 400 a live caller) — rather than presenting it as a violation. Note that this adds two more `ChallengeScreen.jsx` touches beyond the four `outcome:` write sites; the spec's Out of Scope / client-exception wording must be updated to reflect that, and the epic's `NOT included` client-scope bullet should be noted as needing the same widening at implementation time.
