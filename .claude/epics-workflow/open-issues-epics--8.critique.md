## Blocking issues

**1. US8.3's largest task is built on a premise that is no longer true — OI-58's CSP fixes are already on `main`.**
OI-58 says production `main` is missing five Content-Security-Policy fixes that only exist on the `stagging` branch, and US8.3 budgets tasks to port them over via a fresh worktree. Verified at source: local `main` and `origin/main` are the same commit (`9eb2612`), and the `helmet(...)` security-header block in `connect-four/server/index.js` on `main` is **byte-identical** to `stagging`'s (`diff` of the block between the two branches is empty). All five named constants — `PADDLE_CDN`, `PADDLE_ORIGINS`, `GOOGLE_PAY_ORIGINS`, `GOOGLE_FONTS_STYLESHEET`, `GOOGLE_FONTS_FILES` — plus the `fontSrc` and `frameSrc` directives are present on `main` at lines 142–175. `git log main -S"GOOGLE_FONTS_FILES"` shows commit `ae3c006` "fix(csp): allow Google Fonts stylesheet and font files" (2026-07-18) — one of the very commits OI-58 lists as stagging-only — is reachable from `main`. The owner evidently did port it themselves, exactly as OI-58 said they intended.
*Recommended resolution:* rewrite US8.3's CSP tasks from "port the five fixes" to "verify and close out": confirm the block matches `docs/architecture/server-conventions.md` §"CSP Directive Rationale", optionally confirm the deployed build actually emits the headers (a real build + server restart — never under `npm run dev`), and mark OI-58 ✅ RESOLVED with `ae3c006` as evidence. Separately, OI-58's entry ends with a paragraph headed "**Resolved (2026-07-18)**" that is about an unrelated Paddle *static import*, not the CSP — that paragraph is why the entry reads ambiguously, and the closeout should disambiguate it.

**2. The lint baseline is wrong, and the eslint config silently applies zero rules to 141 files — so "get to zero" is achievable without the gate covering 28% of the tree.**
The epic and OI-70 both cite "254 errors / 268 problems". Re-measured just now with `npx eslint . -f json`: **282 errors + 14 warnings across 71 files**, of which 164 are `no-undef` (159 of those are `process`) — the environment-split decision is sound, the number is stale. More consequentially: `connect-four/eslint.config.js` has a single config block with `files: ['**/*.{js,jsx}']`. ESLint 9 still *walks* `.mjs` files (141 of the 501 files it visited), but `npx eslint --print-config server/tests/reasonEngine.test.mjs` returns **0 rules**, versus 78 rules for `server/index.js`. Every `.mjs` file — all of `server/tests/*.test.mjs`, `server/scripts/*.mjs`, `server/*.test.mjs` — is effectively unlinted. Settled decision 1 talks only about browser-vs-node globals and never mentions extension coverage, so a spec written from the epic alone will hit zero errors and wire in a gate that still ignores those files. The number of errors that appear once the glob widens is unknown and unmeasurable until it does — this, more than the fix-now/rule-off triage, is what makes US8.1's task count unpredictable.
*Recommended resolution:* correct the baseline to 282/14 (with the caveat that it is again point-in-time); add `.mjs`/`.cjs` to the config's `files` glob as an explicit task; add an acceptance criterion that a deliberately-introduced error in a `.mjs` file makes `npm run lint` fail (proving the gate, per `testing-conventions.md` §"Grep-as-lint tests must not use bare grep": *"Prove the lint works by temporarily inserting a real violation and confirming it goes red"*). Note also that 3 of the 282 are `Unused eslint-disable directive` reports (`server/index.js:4260`, `server/tests/renderCoverageUniverse.test.mjs:28`, `tests/classifier/classifier.test.js:221`) which will move around as rules change.

**3. US8.2's two test-suite changes both need registry wiring the epic never names, and one of them deletes live coverage.**
(a) The epic says "either wire `deepRevealPhase` into the render or delete it plus its test." `connect-four/tests/unit/deepRevealTimeout.test.js` contains **two** tests: `'phase transitions: loading -> slow -> timedOut…'` (the dead helper) and `'hard cap is well beyond the soft hint…'`, which asserts the constants `DEEP_REVEAL_SOFT_MS`/`DEEP_REVEAL_HARD_MS` — and those constants *are* live, imported at `src/components/DeepRevealPane.jsx:12` and used at lines 184–190. Deleting the whole file drops real coverage. (b) Test files in this repo are never auto-discovered: `test`, `test:fast`, and `test:dom` in `connect-four/package.json` are hand-maintained space-separated file lists. `test:dom` currently names 19 files and contains **no** SplitReveal test, so the new render-level regression will run nowhere unless it is added by name; likewise, deleting the phase test means editing the `test` and `test:fast` strings.
*Recommended resolution:* change the epic's wording to "delete the `deepRevealPhase` export and only its own test case, keeping the constants test", and add an explicit task/acceptance line: "the new SplitReveal DOM test is added by name to the `test:dom` script string and observed running."
