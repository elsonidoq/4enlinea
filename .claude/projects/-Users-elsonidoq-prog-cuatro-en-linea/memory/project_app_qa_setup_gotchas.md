Non-obvious traps hit during the mobile `/app-qa` sweep (2026-07-07). Read before running app-qa.

- **`🛠 Dev: skip auth` mints a NEW empty anonymous user every time** (`signInAnonymously()`), keyed to a fresh device_uuid. It does NOT reuse the prior QA user, so pre-populated games/blunders (owned by an earlier user) are invisible. To QA data-dependent areas: flip the new user to paid + set papergames_id + import via the app, then (because of the bug below) **reassign existing blunders' `user_id` to the new user** — the import's deterministic game ids mean games transfer via upsert but blunders don't.
- **FIXED (migration 053, 2026-07-08)**: `idx_blunders_papergames_unique` now includes `user_id` and `papergames_games` is unique per `(user_id, papergames_room_uid)` — the 2nd-user import collision / silent blunder loss no longer reproduces locally. Prod still needs the migration (+ constraint-name pre-flight) at deploy time; see [[project_papergames_integration]].
- **`resize_page` (chrome-devtools MCP) does NOT actually resize here** — `window.innerWidth` stays put. Use `emulate({viewport:"390x844x2,mobile,touch"})` instead; it persists across navigation.
- **The session drops mid-run** (access token expires, client never auto-refreshes → app shows logged-out "Sign up"). Self-heal WITHOUT re-clicking dev-skip-auth (which strands data): `await fetch('/api/auth/refresh',{method:'POST',credentials:'include'})` then reload. This is itself a shipped bug (client should call refresh on 401).
- **Reaching a clean SIGNED-OUT state locally:** cookie-clearing in DevTools does NOT sign you out — the session is an httpOnly `sb_access_token` cookie you can't clear from the app. Use the **`🛠 Dev: clear IndexedDB & sign out` button on the Settings screen** (localhost-only, gated on `import.meta.env.DEV`, in both the signed-in and signed-out Settings views). It POSTs `/api/auth/signout` (drops the cookie) + clears web storage + wipes local IndexedDB data, then reloads into a genuine signed-out state — the way to QA signed-out UI (e.g. the Stats `signup_prompt` button). It clears object stores in place, NOT `deleteDatabase` (see [[project_indexeddb_signin_hang]] for why deleteDatabase would hang the next sign-in).
- **Fresh full-DB wipe = clean single-user path (no blunder reassignment needed):** if the user has wiped the local DB, dev-skip-auth is the *only* user, so importing papergames as that user stores blunders normally (137 for account `69e773d36bf9938bffc1509a`); the unique-index collision only bites the 2nd user. So a fresh DB is the way to QA blunder-dependent flows without the reassignment dance — but it does NOT prove the index bug is fixed (verify `pg_indexes` for `user_id` in `idx_blunders_papergames_unique`; still absent as of 2026-07-07 round 2).
- **Board discs render as radial-gradient `background-image`, NOT `backgroundColor`** → naive `evaluate_script` disc detectors keyed on `backgroundColor` return 0 filled cells and you'll wrongly think the board is empty. Detect via `getComputedStyle(e).backgroundImage` containing `rgb(67, 198, 115)` (green/P1) vs `rgb(82, 90, 107)` (gray/P2); empty cells are `rgb(251, 244, 227)`. Board cells still lack `role`/`aria-label`, so a11y snapshots can't map the grid. Highlights: light-green ring = correct move, red/salmon ring = played move.
- **FIXED (spec 041, 2026-07-08)**: the coach queue `.limit(50)` cap is gone — `/api/coach/queue` paginates (`limit`≤200/`offset`, true `total`, ordering `severity DESC, created_at ASC, id ASC`), consumers page to completion, and `/mistakes` cards come from `GET /api/coach/category-counts` (count-driven cards only — thumbnails/severity meter deliberately dropped; don't "fix" by reverting to the queue endpoint).
- **Authenticated HTTP tests without a browser**: `supabase.auth.admin.createUser` → `signInWithPassword` with an anon-key client (anon key = `VITE_SUPABASE_ANON_KEY` in `connect-four/.env.local`, NOT `server/.env`) → POST `{access_token, refresh_token}` to `/api/auth/callback` → use returned httpOnly cookies. Works against local Supabase; clean up synthetic users afterward.
- **The shared dev server (port 3001) does NOT hot-reload `server/index.js`** — to verify server changes live, spin a throwaway `PORT=3099 node --env-file=server/.env server/index.js` and kill only that; never kill 3001/5173. Vite hot-reloads frontend changes fine.
- **Local `puzzles` table is often empty** → Challenges set picker renders nothing; re-seed before QA'ing Challenges.
- Tier flips: no email on the anon user, so `set-tier.js` can't find it — flip `users.tier` by direct service-role DB update. Deep-reveal free quota = 20/week (`deep_reveal_count`); set it to 20 to test the 429 + "Become Pro" CTA. Related: [[project_papergames_integration]], [[project_auth_flow_traps]].

## QA server + DB + candidate operational recipe (owner-provided 2026-07-10)

- **Reading server logs during QA**: the dev server writes to the terminal, so to inspect logs you must relaunch with redirection. A dev server is usually ALREADY running (`npm run dev` → a `concurrently` parent + `node --env-file=server/.env server/index.js` on :3001 + `vite` on :5173). **Kill it first** (kill the `npm run dev`/`concurrently`/node/vite group — don't leave the old one bound to 3001/5173), then relaunch redirecting to files, e.g. `cd connect-four && npm run dev > /tmp/cf_dev.log 2>&1 &` (or split server/vite), and `tail -f`/`tail -n` the file. Prefer running the relaunch as a background command. (Note the older gotcha above about a throwaway `PORT=3099` server — that's for verifying a server code change live *without* killing 3001; for QA-with-logs you intentionally own the whole dev server.)
- **Wipe the local DB clean**: `./reset_local_supabase.sh` (just `supabase db reset`) then `./migrate.sh` (applies migrations + baseline check). Use before a clean-slate QA run. A fresh wipe also gives the single-user clean path (see dev-skip-auth note above).
- **Seed Challenges puzzles** (the `puzzles`/`candidates` tables are empty after a wipe → Challenges picker renders nothing): `cd connect-four/server && node scripts/generate_all_candidates.mjs` (POSTs `/api/admin/generate` count=100 for all 12 categories; flags `--dry-run`/`--category`/`--count`/`--port`). Then **approve** the generated candidates and **reindex** so they show up in the Challenges section — endpoints: `POST /api/admin/candidates/:id/approve` (or the bulk `POST /api/admin/candidates` status=approved path ~index.js:3005-3057), then `POST /api/admin/puzzles/reindex` (index.js:2934; `requireLocalhost`). `delete_all_candidates.sh` clears them. Generation needs the server running.
- **`generate_all_candidates.mjs` can time out before all 12 categories finish** — a full run past ~280s seeded only 7/12 categories in one QA session (`undercut`/`overcut`/`claimeven`/`figure_7`/`j_shape` were the ones left unseeded, being solver-heavier). If you need a specific category, seed it directly with `--category <slug>` rather than trusting a single all-categories run to complete; verify per-category counts via `/api/puzzles/counts` before browser-testing.
- **Reason-engine / board TOOLS** live under a worktree: `.claude/worktrees/win-dist-grid/connect-four/server/scripts/reason_engine/TOOLS/` — includes `optimal_line.mjs`, `forward_distance.mjs`, `forward_projection.mjs`, `decisive_check.mjs`, `parity_cells.mjs`, `build_catalog.mjs`, etc. Use these (not hand-rolled solver calls) when working with boards during QA. See [[reference_inline_node_scripts]], [[project_admin_fv_suff_repurposed]].
