Traps for lesson progression + lesson audio (spec 046 territory; some pre-existing).

**Lesson order = filename numeric prefix, NOT the JSON `order` field.** `server/lessonLoader.js:169-176` does `{...lesson, order}` where `order = parseInt(filename.match(/^lesson-(\d+)-/))`, then sorts ascending. The JSON `order` field is **overwritten and ignored**. To reorder lessons you **rename the files** (`git mv`, use git so collisions fail loudly), not edit JSON. `id` is independent of filename, so renames preserve `lesson_progress` records. Free/paid split is by each JSON's `free` flag, not position.

> **Renumbering (2026-07-25).** Reordering needs a **two-phase `git mv`** (all → temp prefixes → final) or intermediate renames collide with existing prefixes. Even though the loader ignores the JSON `order`, keep it in sync with the filename — the curriculum now asserts it. Current state: **15 lessons, all 15 have a `socratic`** (the old "`lesson-04-odd-rows-belong-to-red.json` has `socratic: null`, so 12 of 13" note is obsolete), free 1–10 / paid 11–15 with **exactly one free→paid transition** — tier contiguity is a product requirement the owner enforces, so any insertion must preserve it. Every `lesson-NN-*` filename in older notes predates this renumbering; locate lessons by `id`, never by prefix.

**Lesson audio can't reuse the spec-039 coach TTS pipeline.** That pipeline is keyed end-to-end by **i18n keys** (`scripts/generate-tts.js` scans **`coach.spoken.`** — narrowed from `coach.` on 2026-07-16; registry/manifest keyed by key; runtime `speakCoachMessage(key)` plays by key and is **manifest-gated**). Lesson slide coach messages are **inline free-text** (`slides[].coachMessages[].text`), not i18n keys — so `speakCoachMessage(key)` would **silently no-op** on them. The only reusable seam is `server/ttsProvider.js` `synthesize(text)`. Spec 046 design: hash each concept-slide message's text → MP3 under `public/audio/lessons/` (committed static, no manifest) → store path at `coachMessages[].audio`; playback via `speakDeepReveal(new Audio(path))`, NOT `speakCoachMessage`.

**Socratic coach text — RESOLVED 2026-07-16 (OI-43); the i18n `socratic.*` namespace is GONE.** It used to live in i18n and fall between both TTS pipelines, silent in every language. Owner's ruling — **lesson content is a thing in itself and must not be assembled from i18n keys** — drove the fix: the text now lives in the lesson JSON at **`socratic.messages`**, a phase→array map (`ask`/`wrong1`/`wrong2`/`correct`/`hint`) whose entries have the *same* `text`/`text_es`/`audio`/`audio_es` shape as `slides[].coachMessages`. `SocraticScreen` reads `lesson.socratic.messages[showHint ? 'hint' : phase]` and narrates via `getNarrationQueue` + `speakLessonAudio`, mirroring `ConceptScreen`. Do **not** re-add `socratic.*` or `lesson.<id>.socratic.*` to `en.json`/`es.json` — they were deleted deliberately. `lesson-04-odd-rows-belong-to-red.json` has `socratic: null` (no Socratic board), so it is **12** lessons with socratic content, not 13.

**Lesson messages are walked by THREE independent mechanisms — two unified, one NOT.** `server/lessonAudio.js` exports **`collectMessages(lesson)`** → `[{message, locator}]`, consumed by **both** `generateLessonAudio` and `collectReferencedAudio`. That unification is load-bearing: `collectReferencedAudio` feeds `pruneOrphanedLessonAudio`, which **deletes** unreferenced mp3s, so a walker that generates audio the collector can't see gets its clips deleted as orphans on the next prune. This divergence has already shipped **twice** (once for `audio_es`, once for socratic) — hence one walker, not two. **But `scripts/translate-lessons.mjs` (the `_es` drafting script) is a THIRD, separate walk** that does *not* use `collectMessages` (its locators carry a `.text` suffix and it runs on raw pre-localization lessons). It keeps its own hand-synced `SOCRATIC_PHASES` copy that must stay in the same fixed order as `lessonAudio.js`'s. **Adding a new message location to lesson JSON means editing both `collectMessages` AND the translator** — miss the translator and that copy silently never gets Spanish, which `pickLocalized`'s English fallback then hides.

**`stripEsKeys` is SHALLOW, so `localizeLesson` must rebuild nested structures, never assign into them.** `stripEsKeys(lesson.socratic)` returns an object whose `.messages` is the **same reference** as the raw `_lessons` cache entry. Assigning into it (`s.messages[phase] = …`) mutates the module cache, permanently deleting `text_es` — and `/api/admin/lessons/:id` + `/api/admin/lessons/:id/generate-audio` both read that **raw** cache via `getLessonsAll()`, so the corruption starves the Spanish generator and then persists to disk on save. Rebuild into a fresh object per phase. `tests/unit/lessonLoader.test.js` pins this; a "no `_es` survives in the response" check **cannot** catch it. Related: [[project_lesson_disk_edit_cache_clobber]].

**`<CoachDialog>` renders the speech *bubble* but never plays audio itself** (confirmed
2026-07-13). It has no auto-play; its `m.audio` field only decides whether the 🔁 replay button
shows (gated on `onReplay && hasNarration`). Any screen that wants the coach to actually *speak*
on arrival must call `useCoachSpeech()` + `speakCoachMessage(i18nKey)` in an effect itself (as
`GameScreen`/`ChallengeScreen`/`ReviewScreen` do). Passing a message into `CoachDialog` is never
sufficient — a common mistake (e.g. `OnboardingMissionScreen` shows the greeting but is silent).
Relatedly, **`/admin/audios` is just a view of `server/tts-registry.json`** (via `GET
/api/admin/audio/status`), and that registry is populated by `scripts/generate-tts.js` scanning
**only `coach.spoken.*` keys** (narrowed from `coach.*` on 2026-07-16 — `coach.ui.*` is screen chrome
and is deliberately never synthesized) — so a phrase under any other namespace (e.g.
`socratic.*`, `onboarding.mission.*`) is invisible on the admin page and can never get
generated/approved audio until it's re-keyed under `coach.spoken.*`. A tripwire test
(`coachSpokenNamespace.test.js`) now fails if any registry key sits outside `coach.spoken.`.

**`speakDeepReveal(audio)` in `src/lib/useCoachSpeech.js` is a module-level singleton queue** (file-scope `speechQueue`/`currentSpeechAudio`), shared with deep-reveal narration — pushing lesson clips into it gives "one at a time" playback for free. It does NOT check the global `speechEnabled` toggle; the caller must gate on `speechEnabled` and call `stopSpeech()` on unmount/navigation. Correcting the epic: spec 039 keys by i18n key, NOT text hash — the text-hash idea is the correct *new* lesson design, not a spec-039 attribution. Related: `docs/architecture/coach-audio-conventions.md`, [[project_admin_localhost_directive]].

**Dev-serving trap for `public/audio/lessons/*.mp3`:** in dev, the Express server on **:3001 serves `../dist`** (the built bundle) and does NOT serve `public/` — so `curl :3001/audio/lessons/x.mp3` returns the SPA `index.html` fallback (200, `text/html`), looking broken. **Vite on :5173 serves `public/` directly**, so the actual app fetches lesson audio fine (200, `audio/mpeg`). Test serving against :5173, not :3001. In prod, `vite build` copies `public/`→`dist/` so Express serves it. Also: the Node **server does not hot-reload** ([[project_app_qa_setup_gotchas]]) — after adding the generate/prune routes you must restart it (`node --env-file=server/.env server/index.js`) or the endpoint 404s "Cannot POST". Spec 046 verified end-to-end on localhost (real key at [[feedback_openai_key_present]]): generate → 4 real MP3s → persisted `coachMessages[].audio` → served via :5173 → playback (HTTP 206) → idempotent re-run generates 0.
