## Findings

### 1. Deep-reveal prose leaks raw column notation `c3-c6`; the guard only strips `cXrY`
- **Filed as**: **OI-126**
- **Severity**: minor · **Type**: spec-042 acceptance failure (US5 / FR-017-019, QA:minor F)
- **Area**: deep reveal / response-boundary guard
- **Suspected code location**: `connect-four/server/reasonRenderGuard.mjs:25` —
  `const CXRY_RE = /\bc(\d+)r\d+\b/gi;`
- **Input**: blunder `455c5272-3143-43d4-aa3f-c10f9d061666` (category `forced_win`, Move 8/28, Gray),
  free tier, "What should I have played?"
- **Observed**: served text contains — *"where your support for the **c3-c6** line still matters"*.
- **Expected**: US5 requires no raw internal coordinate tokens in player-facing prose.
- **Evidence**: `stripInternalTokens` rewrites only the `cXrY` form (`c1r4` → "column 1"). A bare
  column token (`c3`) or a range (`c3-c6`) matches neither `CXRY_RE` nor `LABEL_PREFIX_RE`, so it
  passes through untouched. Confirmed by reading the regex at source, not inferred from the output.
  Nothing else catches it downstream — per **OI-124** the annotation gate never runs on the live path.
- **Note**: the other two sampled reveals (`undercut` blunder `31f06fa5…`, `double_threat` blunder
  `a5599ee3…`) were clean of `sev:`, `tree:`, `community-`, `cXrY`, and raw movestrings.

### 2. MistakeDetail Prev/Next does not update the URL, so a reload shows a different mistake
- **Severity**: minor · **Type**: adjacent (not a spec-042 criterion — US3's stepper requirement
  targets the ReviewScreen, which does navigate correctly)
- **Area**: mistake detail stepper
- **Suspected code location**: `connect-four/src/screens/MistakeDetailScreen.jsx` (the `Prev`/`Next`
  handlers that drive the "N of 12" stepper)
- **Repro**: open `/blunder/fdb371b7-2e18-4c37-8ac6-4e039efc4480` → shows `Move 16 / 29`, `6 of 12`.
  Click **Prev** → screen shows `Move 14 / 29`, `5 of 12`, but the address bar still reads
  `/blunder/fdb371b7…`. Reload.
- **Observed**: after reload the screen returns to `Move 16 / 29`, `6 of 12` — a different mistake
  than was on screen before the reload.
- **Expected**: the permalink should track the displayed mistake, so reload/share is stable. This is
  the same reload-survival property US2 establishes for the entry path.

### 3. `quickstart.md`'s US6 zoom criterion is stale — the behavior was deliberately superseded
- **Filed as**: **OI-127** (which additionally records that the contract doc asserts the *opposite*
  outcome, and that `splitRevealZoom.test.js`'s "invariant" case is vacuous)
- **Severity**: polish (documentation) · **Type**: spec/code drift
- **Area**: deep-reveal split pane
- **Suspected code location**: `connect-four/src/components/SplitReveal.jsx:49-72`
- **Detail**: quickstart US6 step 3 asks to "confirm the board's zoom level stays constant across the
  full drag range". The shipped code states the opposite intent verbatim: *"Supersedes spec 042 US6
  (FR-022, SC-009, contracts/split-reveal-zoom-contract.md §2), which FROZE boardW to the open-time
  split… That freeze is the root cause of the reported bug"*. `boardW` is now a `useMemo` over the
  **live** `splitPct`, with a `MIN_BOARD_W = 120` floor so the cap is never dropped to `width:100%`.
- **Action**: update `quickstart.md` (and `contracts/split-reveal-zoom-contract.md`) so the criterion
  reads "board resizes smoothly with the split, never full-bleed, never clipped" — otherwise a future
  QA run will log a false failure.

### 4. Deep-reveal prose names regions that carry no zone annotation, so they can't be highlighted
- **Severity**: minor · **Type**: adjacent (highlight integrity, app-qa rubric)
- **Area**: deep reveal ↔ board highlighting
- **Input**: blunder `a5599ee3-a5f9-404f-b284-014562c6a35e` (`double_threat`, Move 12/31, Gray)
- **Observed**: the text names four board regions — "the bottom row", "column 7", "column 6", "both
  winning squares" — but only **"column 7"** and the term "7-shaped double threat" render as
  interactive annotated spans. "column 6" (the actual fork column the sentence is about) and "bottom
  row" are plain prose and highlight nothing.
- **Expected**: every region the text names should be highlightable.
- **Evidence (positive control — highlighting itself works)**: "column 7" is default-active and draws
  a vertical capsule at `x = 163.146`, which is exactly column 7's measured centre (`163.1`) — no
  off-by-one. Clicking the span toggles the capsule off and on.

returns an empty board and reads as a bug; always wait ~2s before asserting board state. (2) A
multi-step drag split across two `evaluate_script` calls loses pointer tracking — keep a whole drag
